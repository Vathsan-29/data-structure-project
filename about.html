Conclusion

The Student Communication System shows how the data structures of IT23302 work together in a single program. Linked lists keep records that change in size, the queue and the stack follow the order rules of messages and undo, the tree and the hash table make searching quick, the graph handles connections and the heap keeps the most urgent notification at the top. Building and testing the complete program gave a clearer understanding of pointers, dynamic memory and the cost of each operation.

Future enhancements

  • Save student records and messages in files so that they are not lost when the program ends.
  • Add options to edit and delete a student, with matching removal from the tree, hash table and graph.
  • Use an adjacency list for the graph and a balanced tree such as an AVL tree for better worst-case speed.
  • Add a login system with separate roles for students and administrators.
  • Build a graphical interface and send messages between computers over a network.
